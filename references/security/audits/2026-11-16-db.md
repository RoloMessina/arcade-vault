## Verificado OK (por migraciones)
- RLS habilitado en `games`, `scores` y `profiles` (`enable row level security`).
- `games`: solo política SELECT. Sin INSERT/UPDATE/DELETE para clientes.
- `scores`: SELECT público e INSERT `scores_insert_guest_or_own` (`user_id` nulo o `= auth.uid()`). Sin políticas UPDATE/DELETE. La política permisiva `scores_insert_public` se elimina. FK `scores_user_id_fkey` presente (`on delete set null`).
- `profiles`: SELECT público. UPDATE solo propio (`using` y `with check` con `id = auth.uid()`). Check del `username` `^[A-Z0-9_]{3,10}$` y `unique`. Sin política INSERT (solo el trigger). Trigger `handle_new_user` con `set search_path`.
- `REVOKE EXECUTE` sobre `username_disponible` y `rls_auto_enable` para `public`, `anon` y `authenticated`.
- Ninguna política de escritura con `using (true)`. Las `true` son solo de SELECT.
